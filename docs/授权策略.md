# AI-Root 授权策略与确认机制

本文说明 v1.1 起的授权模型：**「持有令牌」不再等于「可执行任意操作」**。

- 审计发现的原始问题与修复方案见 [SECURITY_REFACTOR_AUDIT.md](SECURITY_REFACTOR_AUDIT.md)
- ACL 的三个历史缺陷（A/B/C）见 [安全模型.md](安全模型.md)

---

## 1. 三层判定

每个请求按固定顺序过一遍，**顺序不可调换**：

```text
1. 内置保护（硬编码）        → Deny      策略文件无法覆盖
2. 策略文件里的 deny 规则     → Deny      全部先扫，保证「禁止优先」
3. approved_services 名单    → Allow     动态放行指定服务重启
4. 策略文件里的 allow 规则    → Allow     严格匹配
5. 策略文件里的 confirm 规则  → Confirm   进入确认流程
6. 未匹配                    → default_decision（默认 confirm）
```

三种结果：

| 结果 | 含义 | 能否被绕过 |
|---|---|---|
| `Allow` | 严格匹配的低风险操作，直接执行 | —— |
| `Confirm` | 需要人工确认；无确认通道时**等同拒绝** | 只能由管理员 `approve` |
| `Deny` | 明确禁止 | **任何确认都不放行** |

> 内置保护优先于一切策略：即使你在 `policy.json` 里写一条
> `{"decision":"allow","op":"run_argv","program":"cmd"}`，`cmd` 仍然会被
> 内置的 `builtin:shell-host` 规则拒绝。这是结构性保证，不是配置项。

## 2. 两种执行形态

| 形态 | 命令 | 是否经 shell | 策略能否精确匹配 |
|---|---|---|---|
| **结构化 argv** | `AI-Root exec <程序> [参数...]` | 否（`CreateProcess` 直调） | 能（程序 + 参数前缀 + 目录） |
| 传统 shell | `AI-Root run "<命令>"` | 是（`cmd /C`） | 不能（只能整条确认） |

**推荐一律用 `exec`**。`run` 保留给必须使用 cmd 语义（`for`、`|`、`dir`）的排障场景，
它默认走人工确认。

### 为什么 argv 更安全

- 程序被解析成**绝对路径**（只在 PATH 中查找，**不查当前目录**），避免
  「客户端把 cwd 指向含 `git.exe` 的目录」这种劫持。
- 参数是数组，`&`、`|`、`>` 不会被解释成 shell 语法。
- 审计日志里能看到真实的程序与参数，而不是一层 `cmd /c` 外壳。

### 一个必须说清的取舍

在 LocalSystem 下运行 `python` / `cargo` / `node` 这类解释器或编译器，
**效果上就等于允许任意代码执行**（`build.rs`、`npm postinstall`、`conftest.py`）。
所以本模式的边界不是禁止代码执行，而是：

1. 不允许**间接**执行（`cmd /c`、`powershell -enc`、`mshta`、`rundll32`…）——
   保证每次执行都能被结构化审计；
2. 不允许**不可逆破坏**（格式化、删卷、改引导、清审计、建管理员账户、装服务）；
3. 不允许**改动 AI-Root 自身**（服务二进制、令牌、策略、服务配置）。

如果你需要更严格的边界，把 `mode` 改为 `balanced` 并填 `workspace_roots`，
argv 执行就会被限制在指定目录内。

## 3. 配置文件

位置：`%ProgramData%\AI-Root\policy.json`

ACL：`SYSTEM:(F)` / `Administrators:(F)` / 安装用户:`(R)`
→ **只有管理员能改**。Agent（安装用户身份）只能读。

首次 `install`（或首次服务启动）时自动生成默认策略。查看当前策略：

```powershell
AI-Root policy
```

### 3.1 完整字段

```jsonc
{
  "version": 1,                       // 必须 <= 服务端支持版本，否则降级为「只读」
  "mode": "autonomy",                 // autonomy | balanced | strict | disabled
  "default_decision": "confirm",      // 未匹配时的归宿：allow | confirm | deny

  "workspace_roots": [],              // balanced 模式下的 argv 目录白名单（绝对路径）
  "approved_services": [],            // 允许 restart_service 的服务名（大小写不敏感）
  "trusted_publishers": [],           // update 信任根：证书 SHA-256（64 位 hex）
  "allow_legacy_shell": false,        // true 时 `run` 不再需要逐次确认
  "confirm_timeout_secs": 300,        // 确认请求有效期，钳制到 30..3600

  "rules": [
    {
      "id": "allow-git-status",       // 稳定标识，写入审计；重复 ID 会被拒绝
      "decision": "allow",            // allow | confirm | deny
      "op": "run_argv",               // 可选：约束操作类型
      "program": "git",               // 可选：程序 basename（大小写不敏感，可省 .exe）
      "program_path": null,           // 可选：程序绝对路径（优先级高于 program）
      "arg_prefix": ["status"],       // 可选：参数前缀必须逐项相等（大小写敏感）
      "arg_forbid": [],               // 可选：参数中任意位置出现即「不匹配」
      "target": null,                 // 可选：op 的目标（精确，或 "prefix:*"）
      "cwd_roots": [],                // 可选：工作目录必须落在这些根内
      "note": "只允许查看状态"         // 可选：给人看的说明
    }
  ]
}
```

**匹配语义**：所有填写了的字段都必须满足（AND），不是「任一命中」。
未填写（`null` / 空数组）表示不约束。

**加载失败的处理**（重要）：

| 情况 | 行为 |
|---|---|
| 文件不存在 | 写入默认策略（`mode=autonomy`） |
| JSON 解析失败 | **降级**：除只读查询外全部拒绝 + 审计 `policy_decision` 中标记 `Degraded` |
| `version` 高于支持版本 | 同上（不猜测未来语义） |
| 规则 ID 重复 / allow 规则过于宽泛 / 相对路径 / 指纹格式错 | 同上 |

降级不是「用默认策略继续」—— 否则「破坏策略文件」就等于「放开所有开发工具」。

### 3.2 模式差异

| 模式 | 未匹配时 | argv 白名单 | 传统 shell |
|---|---|---|---|
| `autonomy`（默认） | confirm | 生效 | confirm |
| `balanced` | confirm | 生效，且 cwd 必须在 `workspace_roots` 内 | confirm |
| `strict` | **deny** | 仅在显式规则下 | deny |
| `disabled` | **deny** | 不生效（连 allow 规则也不生效） | deny |

`disabled` 是硬约束：只读查询（`query_system_info` / `query_service` / `read_state_file`）仍可用。

## 4. 默认自动执行的操作

`mode=autonomy` 的默认策略放行以下 argv 程序（**不需要确认**）：

**开发工具链**
`git` `cargo` `rustc` `rustup` `rustfmt` `clippy-driver` `node`* `npm` `pnpm` `yarn` `npx`
`python`* `python3`* `py`* `pip` `go` `dotnet` `java` `javac` `mvn` `gradle`
`cmake` `ninja` `make` `msbuild` `cl` `link` `clang` `clang++` `gcc` `g++` `ld`
`objdump` `nm` `strings` `readelf` `r2` `rabin2` `7z` `tar` `ffmpeg` `magick`

`*` 表示带 `arg_forbid`：`node -e/--eval/-p/--print`、`python -c`、`py -c` 被排除
（这些等于内联任意代码，不属「跑脚本/跑构建」的常规形态）。

**包管理器**（任务书要求的「常用软件安装自动化」）
`winget` `choco` `scoop`

**只读系统信息**
`systeminfo` `ipconfig` `whoami` `hostname` `tasklist` `netstat` `driverquery`
`pnputil` `powercfg` `where`

**结构化只读操作**
`query_system_info` `query_service` `read_state_file`（白名单仅 `policy.json`）

默认**需要确认**：`sc` `reg` `netsh` `schtasks` `takeown` `icacls` `bcdedit` `diskpart`、
未列入 `approved_services` 的 `restart_service`、以及所有传统 shell。

默认**直接拒绝**（内置，不可配置）：

| 类别 | 例子 | 规则 ID |
|---|---|---|
| 间接执行宿主 | `cmd` `powershell` `pwsh` `wscript` `cscript` `mshta` `rundll32` `regsvr32` `wsl` `bash` `sh` | `builtin:shell-host` |
| 下载器 | `certutil`（只放行 `-hashfile/-dump/-verify/-store`）`bitsadmin` `curl` `wget` | `builtin:downloader` |
| 磁盘/引导不可逆 | `format` `diskpart` `bcdedit` `vssadmin delete` `wbadmin delete` `cipher /w` | `builtin:destructive` |
| 关闭安全控制 | `wevtutil cl` `auditpol /clear` `Set-MpPreference` `netsh advfirewall set` | `builtin:destructive` |
| 持久化 | `sc create/delete/config` `schtasks /create` `reg add …\Run` | `builtin:destructive` |
| 提权账户 | `net user … /add` `net localgroup administrators … /add` | `builtin:destructive` |
| 凭据转储 | `procdump` `mimikatz` `pwdump` | `builtin:destructive` |
| 改 AI-Root 自身 | 任何参数指向 `%ProgramData%\AI-Root` | `builtin:self-protect` |
| 管道内更新自身 | `op=update_self` | `builtin:update-gated` |

## 5. 如何添加自动化规则

### 5.1 场景一：放行一个新工具（最常见）

比如想让 `ruff`（Python linter）自动执行：

```jsonc
{
  "id": "allow-ruff",
  "decision": "allow",
  "op": "run_argv",
  "program": "ruff",
  "note": "Python linter"
}
```

改完不需要重启服务 —— 每次请求都会重新读取策略文件。

> 注意：`policy.json` 受 ACL 保护，必须**以管理员身份**编辑：
> ```powershell
> Start-Process notepad "C:\ProgramData\AI-Root\policy.json" -Verb RunAs
> ```

### 5.2 场景二：只允许某个程序的特定子命令

```jsonc
{
  "id": "allow-git-status-only",
  "decision": "allow",
  "op": "run_argv",
  "program": "git",
  "arg_prefix": ["status"],
  "note": "只允许 git status（不带 push/pull）"
}
```

### 5.3 场景三：只在项目目录内允许构建

```jsonc
{
  "id": "allow-cargo-in-workspace",
  "decision": "allow",
  "op": "run_argv",
  "program": "cargo",
  "cwd_roots": ["D:\\project", "C:\\Users\\AprYT\\source"]
}
```

`cwd_roots` 是**硬约束**：请求没给 `--cwd`，或给了不在根内的目录，规则都不匹配。
路径比较按目录边界，`C:\project-evil` 不会被 `C:\project` 误判为子目录。

### 5.4 场景四：放行某几个服务的重启

不用写规则，只改一行：

```jsonc
"approved_services": ["Spooler", "wuauserv", "Dnscache"]
```

之后 `AI-Root op restart_service --target Spooler` 直接执行，不打断用户。

### 5.5 场景五：临时收紧

把 `"mode"` 改成 `"strict"`：未显式允许的一律拒绝（只读查询仍可用）。
改回 `"autonomy"` 即恢复。

## 6. 确认机制

### 6.1 为什么没有弹窗

服务以 LocalSystem 运行在 session 0，**没有交互桌面**，无法弹 UAC/GUI。
任何「服务端弹窗」都需要在用户会话里常驻一个接收端，那是新增攻击面。
所以确认通道做成「文件 + 管理员命令」。

### 6.2 完整流程

```text
① AI 执行一条需要确认的命令
   AI-Root exec winget install SomePackage
   → 退出码 3，输出：
     需要人工确认：
       请求 ID : 52f2d3f6524111b4
       操作    : run_argv
       参数    : argv=[winget install SomePackage]
       风险    : 结构化执行 `winget`：程序与参数已固定……
       有效期  : 300s
     管理员批准：AI-Root approve 52f2d3f6524111b4

② 用户（管理员终端）
   AI-Root approve 52f2d3f6524111b4

③ AI 重新执行**同一条命令**
   → 这次匹配到批准，正常执行；批准被一次性消费
```

其它命令：

```powershell
AI-Root pending            # 列出所有待确认请求（含风险说明）
AI-Root deny <id>          # 拒绝
```

### 6.3 安全属性

| 属性 | 实现 |
|---|---|
| 不可伪造 | `pending\` 目录继承数据目录 ACL，普通用户（含 Agent）**无法写入** `.approved` |
| 与参数绑定 | 批准内容 = `sha256(op \| 完整参数摘要)`；参数改一个字符就是另一个哈希 |
| 一次性 | 批准被消费即删除 |
| 过期即废 | 请求与批准都带 TTL，`approve` 拒绝过期请求 |
| 不接受客户端声明 | 协议 `deny_unknown_fields`，发 `confirmed: true` 会**解析失败** |
| 不占死连接 | 首次请求立即返回（不等确认），批准后重放 —— 不会把并发槽占满 5 分钟 |

## 7. 更新与回滚

### 7.1 更新（`AI-Root update`）

v1.1 起，`update` 有三道门控，**任一不满足即拒绝**：

1. **Authenticode 嵌入签名**通过 `WinVerifyTrust`（catalog 签名不算）；
2. 签名者证书 SHA-256 命中 `trusted_publishers`；
3. 目标路径 = SCM 实际 `ImagePath`，且必须位于 `%ProgramData%\AI-Root`（受 ACL 保护）。

另加：架构必须与当前进程一致、拒绝版本降级、复制后二次比对 SHA-256、
启动 20s 内未 Running 则**自动回滚**到 `.old`。

### 7.2 建立信任根（一次性，需管理员）

```powershell
# 1) 查看发布包签名（不发管理员也行，只读）
AI-Root signature .\AI-Root-new.exe

# 2) 确认「签名者」与「证书 SHA-256」确实是你的发布证书后，加入信任根
AI-Root trust-publisher .\AI-Root-new.exe

# 3) 之后即可自主更新（非提权）
AI-Root update D:\path\to\AI-Root-new.exe
```

未配置 `trusted_publishers` 时，`update` **一律拒绝**（安全失败），
并提示先执行 `trust-publisher`。

> 为什么必须嵌入签名：Windows 系统目录里的程序大多是 **catalog 签名**
> （签名在 `.cat` 文件里，不在 PE 内），`WinVerifyTrust` 的
> `GENERIC_VERIFY_V2` 默认看不到。本实现只接受嵌入签名 —— 比 catalog 更严格，
> 但需要发布流程配合 `signtool sign /fd sha256 /a AI-Root.exe`。

### 7.3 回滚

- **自动**：新版本启动失败/未在 20s 内 Running → 停止 → 恢复 `.old` → 重启旧版本。
- **手动**（离线）：
  ```powershell
  sc stop AI-Root
  Move-Item C:\ProgramData\AI-Root\AI-Root.exe.old C:\ProgramData\AI-Root\AI-Root.exe -Force
  sc start AI-Root
  ```
  注意：`.old` 只在替换后、健康检查通过前存在；成功更新后会删除。
- **版本降级被拒绝**时同样适用上面的手动流程。

## 8. 已知限制

| 限制 | 说明 |
|---|---|
| 令牌仍是全权凭据 | 令牌本身不分级；分级靠策略层。令牌泄漏 = 可发起任意请求（但受策略约束） |
| 解释器 = 代码执行 | 允许 `python`/`cargo`/`node` 即等于允许任意代码（见 §2 的取舍说明） |
| 不检查证书吊销 | `WTD_REVOCATION_CHECK_NONE`：服务可能在无网环境启动，联网检查会长时间挂起。信任根是固定指纹，风险可控 |
| 不验证 catalog 签名 | 只接受嵌入签名（比默认更严格） |
| `pending\` 无自动清理 | 过期请求在下次同参数请求时被覆盖；可用 `AI-Root pending` 查看，管理员可手工删除 |
| 传统 shell 只能整条确认 | 字符串无法结构化匹配；能用 `exec` 就别用 `run` |
| 内置保护是「模式匹配」 | shell 模式下，`f^ormat` 这类 cmd 转义改写可以绕过字符串检查 —— 所以 shell 必须确认，且确认前用户能看到完整命令 |
| 服务可被安装用户停止 | `install` 仍授予 `GRGX`（含 STOP/START），用于零 UAC 更新。现在更新有签名门控，DoS 风险保留（见审计 V-14） |
| 确认需要管理员在场 | 设计如此：确认真实性依赖「只有管理员能写 pending 目录」 |

## 9. 排障

```powershell
AI-Root status                  # 服务状态 / 启用标志 / 管道 / 令牌
AI-Root policy                  # 当前策略与自动允许范围
AI-Root tail                    # 实时事件流
AI-Root tail --type policy_decision   # 只看授权判定
AI-Root tail --type confirm_consumed  # 只看确认被消费
```

审计事件类型：

| type | 含义 |
|---|---|
| `policy_decision` | 每次请求的判定（含 deny 与降级状态） |
| `exec_done` / `command_audit` | 执行结果（含 decision / rule_id / confirmed） |
| `confirm_consumed` | 某份批准被使用 |
| `update_rejected` / `update_rollback` / `update_done` | 更新流程各阶段 |
| `acl_setup_failed` | 启动时 ACL 设置/校验失败（服务会拒绝启动） |
| `temp_cleanup_failed` | 临时脚本清理失败（文件路径会记录） |
| `taskkill_failed` | 超时杀进程树失败（已降级为 kill 直接子进程） |

日志位置：`%ProgramData%\AI-Root\events.jsonl`（实时流，2MB 轮转）、`exec.log`（审计）。
日志中的命令参数经 `redact()` 脱敏（`--password=`、`-p`、`API_KEY=` 等）。
