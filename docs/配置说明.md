# AI-Root 配置说明（v1.2）

本文是 AI-Root 的配置参考。审计背景与问题清单见 [CONFIG_AUDIT.md](CONFIG_AUDIT.md)，
授权模型本身见 [授权策略.md](授权策略.md)。

---

## 1. 三层优先级

```text
① 代码默认值          PolicyFile::default_autonomy()      67 条规则，只读系统信息全放行
② 用户偏好            %LOCALAPPDATA%\AI-Root\user.toml     当前用户可写 —— 只能收紧
③ 管理员授权策略      %ProgramData%\AI-Root\policy.toml    仅管理员可写 —— 权威
   + 规则目录         %ProgramData%\AI-Root\rules.d\*.toml
```

合并顺序：**①→③ 完全覆盖，② 只在"更严"时生效**。

### 为什么用户层只能收紧

用户配置在 `%LOCALAPPDATA%`，Agent 以安装用户身份运行，**它能写这个文件**。
如果用户层能放宽，Agent 就可以「自己给自己发授权」，整套策略形同虚设。

所以：

| 用户字段 | 合并规则 | 举例 |
|---|---|---|
| `mode` | 取更严（`strictness` 取 max） | 管理员 `autonomy` + 用户 `strict` → `strict`；管理员 `strict` + 用户 `autonomy` → **仍 `strict`** |
| `confirm_timeout_secs` | 取更小 | 管理员 300 + 用户 60 → 60；管理员 120 + 用户 600 → **仍 120** |
| `default_timeout_ms` | 直接采用（非授权项），钳制到 `[1000, 600000]` | —— |

`strictness`：`autonomy(0) < balanced(1) < strict(2) < disabled(3)`。

**用户配置里根本不存在** `rules` / `approved_services` / `trusted_publishers` /
`allow_legacy_shell` / `workspace_roots` 这些字段。写了会**报错**（`deny_unknown_fields`），
并导致整层被忽略（结果只会更严），而不是被静默忽略。

## 2. 磁盘布局

### 2.1 机器级（`%ProgramData%\AI-Root\`）

```text
AI-Root.exe                     服务二进制（SCM ImagePath 指向这里）
policy.toml                     管理员授权策略
rules.d\                        自动化规则（按主题拆分，按文件名字典序加载）
  10-dev-tools.toml
  20-services.toml
  90-local.toml
secrets\                        秘密（令牌 = SYSTEM 凭据）
  token.txt
logs\                           可读日志
  events.jsonl                  实时事件流（AI-Root tail）
  exec.log                      审计日志
state\                          运行状态
  enabled.flag                  启用开关
  sid.txt                       安装用户 SID（管道 SDDL 用）
  policy.initialized            「策略已初始化」标记（见 §5）
  layout.version                布局版本（当前 2）
  pending\                      待确认请求
  legacy\                       迁移前的旧策略备份
  tmp\                          SYSTEM 待执行脚本（临时）
```

**为什么拆子目录**：令牌等同 SYSTEM 凭据。与日志/状态分开后，
才能单独收紧 `secrets\` 的 ACL，而不必为了"能看日志"顺带放宽秘密的可见范围。
`tmp\` 里放的是**即将被 SYSTEM 执行**的脚本，也不该和可读日志混在一起。

默认 ACL（由 `install` 设置）：

| 目录 | SYSTEM | Administrators | 安装用户 |
|---|---|---|---|
| 根目录 | F | F | R |
| `secrets\` | F | F | R |

### 2.2 用户级（`%LOCALAPPDATA%\AI-Root\`）

```text
user.toml                       用户偏好（只能收紧）
```

用 `LOCALAPPDATA` 而不是 `APPDATA`：偏好不需要漫游，域环境下漫游目录可能被策略重定向。

## 3. `policy.toml` 字段

```toml
version = 2                  # 必须 <= 程序支持版本（当前 2）
mode = "autonomy"            # autonomy | balanced | strict | disabled
default_decision = "confirm" # allow | confirm | deny（未匹配时的归宿）
workspace_roots = []         # balanced 模式下的 argv 工作目录白名单（绝对路径）
approved_services = []       # 允许直接 restart_service 的服务名
trusted_publishers = []      # update 信任根：证书 SHA-256（64 位 hex）
allow_legacy_shell = false   # true = 传统 shell 不逐次确认
confirm_timeout_secs = 300   # 确认有效期，钳制 30..3600

[[rule]]                     # 规则可内联，也可放 rules.d（推荐后者）
id = "..."
decision = "allow"
...
```

**规则字段**（所有填写的字段都必须满足，AND 语义）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 全局唯一（跨 `rules.d` 也唯一），写入审计 |
| `decision` | `allow` / `confirm` / `deny` | 判定结果 |
| `op` | 操作名 | `run_argv` / `run_shell` / `query_service` / `restart_service` / `query_system_info` / `read_state_file` |
| `program` | 字符串 | 程序 basename（大小写不敏感，可省 `.exe`） |
| `program_path` | 绝对路径 | 优先于 `program`，语义是"必须是这个文件" |
| `arg_prefix` | 字符串数组 | 参数**前缀**逐项相等（大小写敏感） |
| `arg_forbid` | 字符串数组 | 参数中任意位置出现即**不匹配**（用于禁 `python -c`） |
| `target` | 字符串 | op 的目标；精确匹配，或 `前缀:*` |
| `cwd_roots` | 绝对路径数组 | 工作目录必须落在这些根内（按目录边界比较） |
| `note` | 字符串 | 写进审计的说明 |

校验规则（`AI-Root config check` 会逐条检查）：

- `id` 非空且全局唯一；
- `allow` 规则必须至少约束 `op` / `program` / `program_path` 之一（禁止"放行一切"）；
- `program_path` / `cwd_roots` 必须是绝对路径；
- `trusted_publishers` 每项必须是 64 位 hex；
- **未知字段直接报错**（拼错不会被忽略）。

## 4. `rules.d/*.toml`

```toml
# 文件名决定加载顺序（字典序），建议用数字前缀表达意图：
#   10- 开发工具   20- 系统维护   90- 本机特例

[[rule]]
id = "dev-git"
decision = "allow"
op = "run_argv"
program = "git"
note = "版本控制"
```

加载规则：

- 只读 `.toml`（大小写不敏感）；
- 按**文件名字典序**合并到策略末尾（内联规则在前）；
- **任一文件解析失败 → 整个策略降级**（`locked_down`）。
  不能"跳过坏文件继续"：被跳过的可能正是 `deny` 规则，跳过等于放宽。
- 规则 `id` 跨文件重复 → 同样降级。

## 5. 失败处理（fail closed）

| 情况 | 结果 |
|---|---|
| `policy.toml` 解析失败 / 校验失败 | `locked_down`：只读查询以外全部拒绝 |
| `policy.toml` 存在但版本高于程序 | `locked_down` |
| `policy.toml` **缺失但有 `state\policy.initialized`** | `locked_down`（**不重建默认**） |
| 首次（无策略、无标记） | 生成默认 `policy.toml` + 写标记 |
| 任一 `rules.d/*.toml` 解析失败 | `locked_down` |
| 规则 id 跨文件重复 | `locked_down` |
| 用户配置解析失败 / 含禁用字段 | **忽略用户层**（保持管理员策略）+ 记录错误 |
| 布局迁移失败 | 服务拒绝启动（`ensure_token` 返回错误） |

### 关于 `policy.initialized`

审计发现的 C-02：旧实现「策略文件不存在 → 自动写默认策略」。默认策略是
`autonomy`（67 条规则允许开发工具），所以**删掉配置文件 = 权限回到出厂宽松状态**。

现在引入标记文件区分两种"不存在"：

- **首次安装**（无标记）→ 生成默认；
- **曾初始化后被删除**（有标记）→ 降级，并在 `config check` 里明确提示。

恢复方式：

```powershell
# 从备份恢复
Copy-Item C:\backup\policy.toml C:\ProgramData\AI-Root\policy.toml
# 或者明确选择"重新出厂"
Remove-Item C:\ProgramData\AI-Root\state\policy.initialized
AI-Root config init
```

## 6. 版本与迁移

### 6.1 策略结构版本

- **v1**：JSON 单文件 `policy.json`，规则内联在 `rules` 数组（≤ 1.1.0）
- **v2**：TOML `policy.toml` + `rules.d\*.toml` + 严格字段校验

处理规则：

| 读到 | 行为 |
|---|---|
| `version = 1` 的 **TOML** | 按 v2 解释（字段是子集关系），不改写文件 |
| `version = 1` 的 **JSON**（`policy.json`） | 迁移为 `policy.toml`，原文件备份到 `state\legacy\policy.json` |
| `version = 2` | 正常 |
| `version > 2` | 拒绝（不猜未来语义） |

### 6.2 磁盘布局迁移

v1.1 是扁平布局（token/日志/策略全在根目录），v1.2 改为分层。

触发时机：`AI-Root install` 或服务启动时（`ensure_token` 内），以及
`AI-Root config migrate`（管理员手动）。迁移是**幂等**的。

迁移原则：

- **不覆盖**已存在的目标文件（跳过并记录，源文件保留）；
- 跨卷 `rename` 失败时退化为 `copy + 长度校验 + 删除`；
- 任一失败 → 返回错误，服务拒绝启动（不留"迁移到一半"的状态）；
- 迁移前先备份旧策略。

```powershell
# 手动执行（管理员）
AI-Root config migrate
```

### 6.3 回滚到旧版本

⚠ **布局迁移后，旧版本 AI-Root 读不到令牌与策略**（路径变了）。回滚步骤：

```powershell
sc stop AI-Root
# 1) 停用新布局：把关键文件放回根目录
Move-Item C:\ProgramData\AI-Root\secrets\token.txt C:\ProgramData\AI-Root\token.txt
Move-Item C:\ProgramData\AI-Root\state\enabled.flag C:\ProgramData\AI-Root\enabled.flag
Move-Item C:\ProgramData\AI-Root\state\sid.txt C:\ProgramData\AI-Root\sid.txt
# 2) 策略回到 JSON（用迁移前的备份）
Copy-Item C:\ProgramData\AI-Root\state\legacy\policy.json C:\ProgramData\AI-Root\policy.json
# 3) 换回旧 exe 后启动
sc start AI-Root
```

因此**升级前请确认已备份** `C:\ProgramData\AI-Root\`。

## 7. 命令

```text
AI-Root config check      校验所有层（只读，不创建/不迁移任何文件）；有错退出码 1
AI-Root config show       显示合并后的生效配置（--json 供程序消费）
AI-Root config path       打印各配置文件路径
AI-Root config init       生成默认管理员策略（管理员；已存在则不覆盖）
AI-Root config migrate    执行旧布局/旧格式迁移（管理员）
AI-Root policy            策略摘要（面向日常查看）
```

`config check` 输出示例：

```text
AI-Root 配置检查
  [OK]   授权策略    已加载
  [OK]   规则 10-dev-tools.toml            已加载
  [OK]   用户偏好    已加载

生效结果：
  模式        : strict
  规则数      : 14
  确认有效期  : 60s

说明：
  - 用户配置收紧模式：autonomy → strict
```

错误示例（拼错字段）：

```text
  [FAIL] 授权策略    解析 ... 失败: TOML parse error at line 3, column 1
3 | trusted_publisher = []
  | ^^^^^^^^^^^^^^^^^
unknown field `trusted_publisher`, expected one of `version`, `mode`, ...
```

## 8. 常见任务

### 8.1 放行一个新工具

```powershell
notepad "$env:ProgramData\AI-Root\rules.d\90-local.toml"   # 需管理员
```

```toml
[[rule]]
id = "local-ruff"
decision = "allow"
op = "run_argv"
program = "ruff"
note = "本机加：Python linter"
```

然后 `AI-Root config check`。无需重启服务。

### 8.2 放行某几个服务的重启

`policy.toml` 里加一行：

```toml
approved_services = ["Spooler", "Dnscache", "wuauserv"]
```

### 8.3 临时收紧（不改管理员策略）

```powershell
notepad "$env:LOCALAPPDATA\AI-Root\user.toml"
```

```toml
version = 2
mode = "strict"
```

删掉这个文件即恢复。

### 8.4 只允许在项目目录内构建

```toml
mode = "balanced"
workspace_roots = ["D:\\project"]
```

或对单条规则更精确：

```toml
[[rule]]
id = "cargo-in-workspace"
decision = "allow"
op = "run_argv"
program = "cargo"
cwd_roots = ["D:\\project"]
```

### 8.5 建立 update 信任根

```powershell
AI-Root signature .\AI-Root-new.exe     # 先看签名者与指纹
AI-Root trust-publisher .\AI-Root-new.exe   # 管理员，写入 policy.toml
AI-Root config check
```

## 9. 排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 所有操作突然被拒 | 策略/规则文件解析失败 → 降级 | `AI-Root config check` 看 `[FAIL]` 行 |
| `update` 说"未配置可信发布者" | `trusted_publishers` 为空或字段拼错 | `config check` + `trust-publisher` |
| 改了策略但不生效 | 改的是 `rules.d` 里被覆盖的规则；或改错了文件 | `config show` 看生效值与 `notes` |
| 用户配置没效果 | 方向是放宽（被忽略） | 看 `config show` 的「说明」段 |
| 服务起不来，事件里有 `acl_setup_failed` | 目录 ACL 校验失败 | 检查 `%ProgramData%\AI-Root` DACL |
| 令牌找不到 | 布局迁移后仍在旧路径 | `AI-Root config migrate` 或手工移动 |

## 10. 已知限制

| 限制 | 说明 |
|---|---|
| 用户层不能加规则 | 这是**设计**，不是缺陷：Agent 可写该文件 |
| 环境变量仍可覆盖路径 | `AIROOT_DATA_DIR` / `AIROOT_USER_DIR` / `AIROOT_PIPE_NAME` 仅用于测试/隔离；服务进程的环境独立于用户 shell，不影响生产路径 |
| 规则仍是"程序名 + 参数"粒度 | 无法表达"只允许 `git status` 且不含 `--upload-pack`"这类深层语义；需要更细就用 `program_path` + `arg_prefix` 收紧 |
| 迁移不可自动回滚 | 回滚需手工移动文件（见 §6.3） |
| 无 GUI 配置编辑器 | 配置是 TOML + `config check`；没有可视化编辑 |
| 布局迁移需管理员 | 服务以 SYSTEM 运行时自动完成；非提权手工执行会失败 |
