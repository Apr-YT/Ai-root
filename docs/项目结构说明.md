# 项目结构

仓库的目录组织与各文件职责。只描述职责，不记录行数，行数随迭代变化，
写进文档必然过时（上一版正是因此失真：它声称 `server.rs` 1,247 行，实际已超过 2,000 行，
并漏掉了后来新增的 4 个模块）。

---

## 目录结构

```text
AI-Root/
├── src/                      # Rust 源码（见下节）
├── scripts/                  # 一键脚本（PowerShell，UTF-8 with BOM）
├── docs/                     # 设计与参考文档
│   ├── audit/                # 历史审计记录（非当前行为依据）
│   └── examples/             # 集成示例
├── examples/                 # 可直接使用的配置示例（policy / rules / user）
├── assets/                   # 应用图标与资源脚本（AI-Root.ico / AI-Root.rc）
├── .cargo/config.toml        # 构建配置（单一事实来源）
├── .github/workflows/ci.yml  # CI：windows-latest，msvc + gnu 双 job
├── .gitignore / .gitattributes
├── build.rs                  # 构建脚本：嵌入 Windows 资源
├── build.sh / build.ps1      # 底层构建入口（CI 与 scripts/build.ps1 共用）
├── Cargo.toml / Cargo.lock   # 依赖与发布配置
├── README.md / CHANGELOG.md
└── LICENSE
```

安装、卸载、体检这些面向用户的操作统一走 `scripts/`，根目录不再保留独立的安装脚本。

## 源码模块（`src/`）

| 文件 | 职责 |
|---|---|
| `main.rs` | CLI 入口、子命令分发、终端输出与着色 |
| `config.rs` | 三层配置加载与合并（默认值 < 用户偏好 < 管理员策略）、`rules.d` 合并、布局/格式迁移、文件指纹缓存 |
| `policy.rs` | 授权策略引擎：`Allow` / `RequireConfirmation` / `Deny` 判定，内置不可覆盖保护，程序/参数/目录约束，策略自校验 |
| `consent.rs` | 文件型人工确认通道：`pending\` 请求、`approve` / `deny`、参数哈希绑定与一次性消费 |
| `signature.rs` | Authenticode 嵌入签名验证（WinVerifyTrust）、发布者证书指纹提取、SHA-256 |
| `protocol.rs` | 帧协议 v2：长度前缀、`Request` / `Response` 结构、严格字段与长度校验、管道连接 |
| `exec.rs` | 执行引擎：结构化 argv 直调（不经 shell）、传统 shell 模式、超时终止、输出上限与 UTF-8 安全截断 |
| `common.rs` | 共享基础设施：令牌生成/存储/轮转、路径解析、目录 DACL 设置与二进制校验、日志脱敏、事件记录 |
| `server.rs` | 管道服务端：客户端鉴权与节流、策略判定、确认流程、并发控制、审计落盘 |
| `service.rs` | Windows 服务生命周期：注册/卸载/启停、DACL 授权、失败恢复策略、签名门控更新与回滚 |
| `winapi_raw.rs` | Win32 API 原始声明（ACL、签名、服务恢复策略） |
| `build.rs` | 资源嵌入：msvc 调 `rc.exe`，gnu 调 `windres -O coff` |

## 脚本（`scripts/`）

| 脚本 | 作用 | 需要管理员 | 改系统状态 |
|---|---|---|---|
| `_common.ps1` | 共享库：输出、仓库定位、exe 解析、管理员检测、UTF-8 解码、AI-Root 调用封装 | — | — |
| `doctor.ps1` | 环境体检：工具链 / 链接器 / SDK / 路径编码 / 配置 / 服务，输出修复建议 | 否 | 否 |
| `build.ps1` | Release 编译，输出 EXE 路径与 SHA256 | 否 | 否 |
| `test.ps1` | 运行测试，区分通过 / 失败 / 环境跳过 | 否 | 否 |
| `install.ps1` | 安装或更新；UAC 自提权、幂等、`-PreflightOnly`、装后自检 | 是（自动提权） | 是 |
| `uninstall.ps1` | 卸载；清单预览、默认备份、`-Purge` 才彻底删除 | 是（自动提权） | 是 |
| `dev.ps1` | 统一入口：`-Action doctor\|build\|test\|install\|uninstall\|all` | 取决于动作 | 取决于动作 |

所有 `.ps1` 必须存成 UTF-8 with BOM。PowerShell 5.1 按系统 ANSI 代码页读取脚本，
没有 BOM 的 UTF-8 中文会变成乱码，甚至因为乱码产生不配对的引号而报语法错误。

## 配置与运行时数据

| 位置 | 内容 | 谁可写 |
|---|---|---|
| `%ProgramData%\AI-Root\policy.toml` | 管理员授权策略（权威） | SYSTEM / Administrators |
| `%ProgramData%\AI-Root\rules.d\*.toml` | 自动化规则（按主题拆分，字典序合并） | SYSTEM / Administrators |
| `%ProgramData%\AI-Root\secrets\token.txt` | 共享令牌（等同 SYSTEM 凭据） | SYSTEM / Administrators |
| `%ProgramData%\AI-Root\logs\` | `exec.log` / `events.jsonl` | SYSTEM |
| `%ProgramData%\AI-Root\state\` | 启用标志、安装用户 SID、待确认请求、临时脚本 | SYSTEM |
| `%ProgramData%\AI-Root\AI-Root.exe` | 服务实际运行的二进制 | SYSTEM / Administrators |
| `%LOCALAPPDATA%\AI-Root\user.toml` | 用户偏好（**只能收紧**，不能放宽） | 当前用户 |

仓库内 `examples/` 提供这三类配置的示例，可直接复制后修改。

## 关键设计约定

1. **令牌不等于授权**：持有令牌只决定「能否发起请求」，每个请求仍要过策略判定。
2. **fail closed**：策略不可解析、ACL 校验失败、签名不可信时一律拒绝，不降级放行。
3. **只接受嵌入签名**：catalog 签名（`System32` 常见）不被 `update` 通道接受。
4. **用户层只能收紧**：`user.toml` 可提高严格度、缩短确认有效期，但不能加规则或放宽模式。
5. **仓库路径尽量纯 ASCII**：MinGW 的 `ld`/`dlltool` 无法正确处理中文路径；脚本会自动
   把产物目录切到 `%LOCALAPPDATA%\AI-Root\build-target`。
